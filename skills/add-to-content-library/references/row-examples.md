# Row examples

Read this before drafting. One example row per Type, then a before/after showing why the format is strict. All titles, URLs, competitors and numbers here are fictional (Example Feedback is a made-up customer feedback platform); they show the shape and density a good row should have.

## Benchmark (Product tab)

```
Topic: In-app survey benchmarks
Actual URL: https://example.com/reports/in-app-survey-benchmarks/
Type: Benchmark
Lead with: Event-triggered surveys reach 12% response rate vs 6% for time-delayed surveys
Biggest takeaways:
1. In-app surveys hit an 8% median response rate and 70% completion.
2. Event-triggered surveys reach a 12% response rate, about double a delayed one.
3. Centered placement gets 14% vs 8% for a corner slide-in.
Sales angle: Behavior-triggered, well-placed surveys roughly double response rates, so "surveys annoy users" is a setup problem, not a channel problem.
CS angle: When an in-app survey underperforms, fix placement and trigger first (centered, instant or event-based) before touching the questions.
```

## Competitor (CX tab)

```
Topic: Northwind Insights alternatives
Actual URL: https://example.com/blog/northwind-insights-alternatives/
Type: Competitor
Lead with: 12 question types vs 5, self-serve with published pricing
Biggest takeaways:
1. Northwind Insights has five question types vs 12 at Example Feedback.
2. In-app surveys gated to its top plan, pricing hidden behind a sales call.
3. Northwind Insights wins for frontline coaching, leaderboards and team huddles.
Sales angle: One platform for NPS, CSAT, CES and in-product feedback that reaches their CRM and help desk, with pricing they can see and a trial they can start today. If their frontline is an app, not a branch, Northwind's coaching layer is cost they'll never use.
CS angle: Get the two-way CRM and help desk sync live in week one so every detractor lands where the team already works, then open a Research Projects project to show the themes behind the scores.
```

Note where the honest point sits: "Northwind Insights wins for frontline coaching" is takeaway 3. The angles still argue for Example Feedback.

## Guide (Research tab)

```
Topic: Building a research repository
Actual URL: https://example.com/blog/building-a-research-repository/
Type: Guide
Lead with: A stakeholder question becomes a cited research report in days, not weeks
Biggest takeaways:
1. Taxonomies, tags and folders turn researchers into maintainers.
2. Repositories get unveiled to an empty room.
3. Project-first: a stakeholder question becomes a cited report, with no manual upkeep.
Sales angle: Use the "librarian trap" story with teams that built a repository nobody opens.
CS angle: Help them open one research project per stakeholder question, rather than putting every question in a single project and tagging insights the way a traditional repository works.
```

## Product news (Marketing tab, written for marketers)

```
Topic: Example Feedback Connector for AI assistants
Actual URL: https://example.com/blog/ai-assistant-connector/
Type: Product news
Lead with: Ask your AI assistant a question and get one answer that combines your Example Feedback data with any other source the assistant can reach, from analytics and CRM data to docs and uploaded files.
Biggest takeaways:
1. Read surveys, responses and research reports from your AI assistant.
2. Drafts new surveys and research projects; nothing goes to respondents.
3. One-time OAuth connection, existing workspace permissions respected.
Sales angle: For teams already working in an AI assistant, demo one chained thread: pull the top churn reasons, check the issue tracker for existing tickets, and draft the missing one.
CS angle: Help each customer connect the Example Feedback Connector next to the tools they already use in their AI assistant, like their CRM or product analytics, and run one first question that combines them.
```

The same piece sits in all four tabs, which is allowed for platform-wide product news, but each tab's angles are rewritten for that persona. The CX version leads with "Detractor verbatims in one prompt, no exports" and the Research version with "Your research, inside the assistant you already use".

## Why the format is strict: before and after

This is what a first version of a library row tends to look like. One cell, one sentence, lifted from the content team's file:

> Position Example Feedback's first-party CES data (500 surveys, 200 companies, 72% median) against the decade-old analyst figure competitors still quote, and use the format gap (page 81% vs widget 70% CES; mobile 24% vs widget 8% response rate) to show why channel choice, not just the metric, matters.

Accurate, and unusable at a glance: seven numbers in one sentence, no entry point. The same content as a library row:

```
Lead with: First-party CES data vs the decade-old analyst figure competitors quote
Biggest takeaways:
1. 72% median CES from 500 surveys across 200 companies.
2. Page surveys 81% vs widgets 70%.
3. Mobile 24% response rate vs widget 8%.
Sales angle: Channel choice, not just the metric, decides the result.
```

Nothing was lost. A rep can read it in five seconds and knows which number to open with.
